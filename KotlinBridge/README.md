# Linking the original InnerTubeX Kotlin framework (optional)

GlassTube ships a pure-Swift InnerTube engine (`GlassTube/Networking/`) that
mirrors the **InnerTubeX API surface** — endpoint paths, client profiles
(`WEB`, `IOS`, `ANDROID_VR`, `WEB_REMIX`), the header contract and the
player fallback chain all match
[MetrolistGroup/innertubex](https://github.com/MetrolistGroup/innertubex)
**v0.13.1**. That keeps the app buildable without any native dependency.

If you want to link the **original Kotlin Multiplatform framework** instead
(the same library Metrolist uses), follow these steps.

## 1. Build the xcframework

On macOS (or via the `Build InnerTubeX iOS framework` workflow in this
repo, which produces the `InnerTubeX-xcframework` artifact):

```bash
git clone https://github.com/MetrolistGroup/innertubex.git -b v0.13.1
cd innertubex
./gradlew linkReleaseFrameworkIosArm64 linkReleaseFrameworkIosSimulatorArm64

xcodebuild -create-xcframework \
  -framework build/bin/iosArm64/releaseFramework/innertubex.framework \
  -framework build/bin/iosSimulatorArm64/releaseFramework/innertubex.framework \
  -output ../Frameworks/InnerTubeX.xcframework
```

## 2. Link it into the app

1. Drop the folder at `Frameworks/InnerTubeX.xcframework` in this repo.
2. Open the generated Xcode project and add the framework under
   **Target → General → Frameworks, Libraries, and Embedded Content**
   (Embed & Sign).
3. Import and construct the client from Swift:

```swift
import InnerTubeX
import Ktor   // exported transitively by the framework

// iOS uses the Darwin engine (OkHttp is Android/JVM-only).
let httpClient = HttpClient(engine: Darwin())
let client = InnerTube(httpClient: httpClient)

client.search(query: "lofi") { response, error in
    // KMP exports suspend functions as completion-handler calls.
}
```

> Symbol names are generated by Kotlin/Native and can shift between
> library versions — verify against the framework's generated
> `innertubex.h` header after building.

## 3. Swap the engine

`AppEnvironment` holds the single `tube = InnerTube()` instance. Replace it
with a wrapper that calls the Kotlin client and returns the same
`VideoItem` / `PlayerStream` values — the UI layer needs no changes.

## Notes

- innertubex is GPL-3.0; GlassTube is GPL-3.0 for the same reason.
- The `Build InnerTubeX iOS framework` workflow is `continue-on-error`:
  KMP linkage can break when upstream dependencies (Ktor, QuackJS) change.
  The main IPA build never depends on it.
